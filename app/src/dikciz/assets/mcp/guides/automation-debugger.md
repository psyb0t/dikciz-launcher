# Automation debugger

Open Dikciz > Automation debugger for retained events, handlers and shared commands. Filter by kind, page through history and tap a record to inspect its causal trace. Event records offer retained payload inspection and simulation against a current script or custom app. Skills, agents & rules is another direct Dikciz menu route.

automationHistory (MCP dikciz_automation_history) supports exact kind/name/outcome/traceId/recordId filters, limit 1..200 and offset 0..1000000. Results are newest first with total and hasMore. Records carry id, traceId, parentId, kind, name, sourceRevision, startedAt, finishedAt, trigger, outcome and code. A trace links the dispatched event to synchronous script/app handlers and their commands, plus queued assistant turns. Separate commands outside such a scope start their own traces. Metadata excludes arguments, results and event payloads. Asynchronous WebView callbacks start separate command traces; use command activity for their widget identity.

SQLite keeps finished trace metadata for seven days and up to 20000 records, pruned during recording and reads. Running rows become interrupted after process death. This records work observed after this feature was installed, not every Android operation or historical work. Event payloads remain in the separately bounded journal, default 60 minutes, 2048 events and 8 MiB. automationHistoryEvent takes an event recordId and checks current Android source permissions. Expired, omitted and restarted-journal payloads return explicit errors. A completed command only means its executor returned; check delivery or launch verification separately.

automationSimulate (MCP dikciz_automation_simulate) accepts exactly one scriptId, appId or source (language lua/javascript), plus event {type,payload,source?,timestampMilliseconds?,coalescingKey?} or a recorded event recordId. It executes the current handler with a state snapshot and current Android grant metadata; androidAccessSource identifies that context. Every command callback is intercepted, even reads; returned actions are not applied. No state, file, schedule or emitted-event effect is executed. Optional ordered replies [{type,result}] provide fake results for branches; their types must match intercepted commands. Missing fixtures return {state:"simulated"}. Inspect simulated, sourceRevision, outcome, code, commands, actions, actionDetails and result. This tests a handler, not subscription filters, policy decisions or actual Android effects. Limit 100 intercepted commands and 256 KiB output.

Simulation can reveal current source/state-derived values and retained event payloads. Grant it only to clients allowed to inspect that information. It remains read-only because it intercepts all effects. Library management is mutating and remains hidden/blocked in read-only chat. Read the bundled dikciz-debug-automation skill through assistantLibrary for the diagnostic procedure.
