# Owner skills, agents and rules

Files live under /sdcard/Dikciz/assistant. Optional AGENTS.md, CLAUDE.md and SOUL.md guide chat. rules/*.md load with their scope metadata. They cannot override executor permissions. Skills are skills/NAME/SKILL.md with YAML name and description, then Markdown instructions. Names match their directory, lowercase letters/digits/hyphens, at most 64 characters. Descriptions are at most 1024 characters. Supporting references/scripts/assets load on demand and do not execute merely by reading them.

assistantLibrary, MCP dikciz_assistant_library: action list returns metadata and relative paths; action read requires path and returns text. The built-in phone_library wrapper provides these reads. Skill metadata enters chat; call phone_library to read relevant instructions. An explicit $skill-name in an owner message loads that skill. Rules and catalog reload between rounds. Entry sha256 revisions change with instruction content; re-read a loaded skill after its revision changes. Missing shared-storage access returns file_access_denied with permission guidance.

agents/NAME.md has name, description, optional readOnly, tools, disallowedTools and model, then its prompt. phone_agent takes exact name and self-contained prompt, runs an isolated persistent conversation and returns its conversationId and answer. Parent cancellation/timeout and read-only restrictions apply. Delegation is limited to two levels. tools/disallowedTools use exact Dikciz MCP names and narrow discovery/execution; they never grant access. model:inherit uses the parent's model; explicit model, contextTokens, maxOutputTokens, maximumRounds, timeoutMilliseconds and reasoning select child settings. Set appropriate budgets for a different model. settings.agent selects a named agent on an ordinary conversation; read its current transcript for results.

Portable directories within assistant: .agents/skills, .claude/skills, .hermes/skills, .agents/agents, .claude/agents, .agents/rules and .claude/rules. Scalar, quoted and indented block/list front matter is supported; complex harness configurations are not. Duplicate identities, malformed metadata, executable hooks, permission modes, MCP definitions, YAML tags/anchors, symlinks and escaped paths reject clearly. Path scopes guide the model; use read-only mode/token grants for enforced boundaries.

Bounds: 512 files, 128 entries, 12 directory levels, 64 KiB per file, 512 KiB instruction data and 128 KiB injected owner instructions/catalog. Context-budget checks still apply. Keep secrets out. Install files through authorized file writes. Encrypted backups include the entire assistant directory. Read the full assistant-library guide through documentation search for examples and compatibility limits.


For native editing and revision-checked writes, read [instruction management](dikciz://docs/guides/assistant-manager).
