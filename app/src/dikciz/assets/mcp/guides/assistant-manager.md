# Manage assistant instructions


Open Dikciz > Skills, agents & rules for the native manager. Tap an item to edit its complete Markdown; More contains Enable/Disable and confirmed Delete. New instruction creates a skill, agent or rule. Validate preserves the draft; errors and revision conflicts do not dismiss it. Supporting files remain after instruction deletion. Disabled files end in .disabled and stop loading. Bundled guides are read-only and separate from owner entries.

assistantLibrary action inspect returns enabled/disabled owner entries, validation errors and bundled guides. read returns text and a raw UTF-8 revision hash. action list preserves the enabled owner entries array and adds builtins. Built-in paths @builtin/dikciz-write-skill/SKILL.md, @builtin/dikciz-write-agent/SKILL.md, @builtin/dikciz-write-rule/SKILL.md and @builtin/dikciz-debug-automation/SKILL.md always load from the APK. Their metadata enters chat and their bodies load on demand. They teach authoring and verification without embedding credentials or private examples.

assistantLibraryValidate (dikciz_assistant_library_validate) takes relative path and complete text. assistantLibraryManage (dikciz_assistant_library_manage) takes action save/setEnabled/delete, path and expectedRevision. save requires text. setEnabled requires enabled. Read the current file first and use its revision; empty expectedRevision creates a missing file only. Conflicts return assistant_revision_conflict. Saves are atomic and validate before replacement; invalid source remains available for repair through inspect. Calls share HTTP/WebSocket/MCP and local script/widget bindings. Scoped tokens need the exact operation grant. Read-only chat hides the manager tool and blocks direct writes. Owner-authored instructions never elevate access.
