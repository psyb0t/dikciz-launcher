# Custom apps

Owner apps live in /sdcard/Dikciz/apps/<id> with app.json, ui.html, ui.css, ui.js, main.js or main.lua, state.json and files/. Dikciz > Apps manages complete bundles. Bundled SOS, Voice notes, Agenda, Device status and Travel todo use the same platform. See recipes/travel-todo for a GPS checklist. SOS decisions are editable JS; native code hosts Android commands, timers and urgent windows.

Discover customAppsList, customAppRead, customAppInstall, customAppControl, customAppEvent, customAppState, customAppSchedule, customAppAlert and customAppRuntime. MCP uses dikciz_custom_apps_list and dikciz_custom_app_* names. All require owner authority; read-only agents see list/read/runtime only and executor guards still block writes.

Install with manifest plus html/css/javascript/backgroundSource and confirm true. Manifest requires version 1, id, title, description, language lua|javascript, events array; commands is optional legacy metadata. Optional eventSubscriptions uses ordinary native filters/intervals; locationMonitoring requests a location service while timers exist. New apps start enabled with Dikciz Android access. Control enable starts without approval; open starts the app and requests UI. Inspect read.uiVisible or snapshot for actual presentation. Open uses a separate Android task per app with no manager toolbar; repeated opens reuse it. Home preserves its Recents entry and Back exits the UI. Manage bundles through Dikciz > Apps. Control disable stops pending work; remove requires confirm true and deletes state/files. Export excludes state and recordings; import validates a .dikciz-app.zip. Replacement and edits preserve running/stopped state; no manifest approval is required. New ID means independent state. Bundled updates preserve edited sources.

JS synchronous onEvent(event), Lua on_event(event). Context has immutable state/scriptId/androidAccess. Return optional status, result object and patchState/emitEvent actions. Other actions are rejected. context.request executes phone commands with Dikciz Android access, returning canonical result/error. App-specific read/state/event/schedule/alert default to self and accept another explicit appId. Apps can administer installations and use shell/files/SDK access already granted to Dikciz; this is not an Android process sandbox.

UI uses window.dikciz, selfWidget state/storagePath and dikciz-state events. The UI may invoke its backend with customAppEvent. Backend runs without WebViews or browser timers; globals are fresh. Source/state changes refresh their relevant consumers. Use customAppRuntime clocks and native access observations.

Schedule action schedule requires timerId/event/delayMilliseconds, optional payload. Delay 1000..604800000 ms, max64 pending. cancel needs timerId; cancelAll cancels this app. Timers persist and use monotonic time/native alarms. A claimed interrupted timer or rebooted pending timer becomes needs_review, not replayed; app.resume signals interruption. Android may delay or reject starts. Read latest run/timers for outcomes.

Alert action show requires episodeId/durationMilliseconds/title/detail/cancelLabel/cancelEvent, optional announcement/finalAnnouncement with {seconds}. Duration 1000..3600000 ms. One urgent app at once. Native modal dims background; overlay access allows other apps, otherwise foreground dialog. Notification/channel/keyguard restrictions apply. Cancel invokes the app event; its code cancels timers/state. close clears resources. Pause apps notification disables pending apps. interruptRunning true on an owner customAppEvent blocks subsequent write calls in a running handler except cleanup/state (including geofence deletion); submitted effects remain.

Limits:64 apps,256KiB each source,128KiB state,depth16,2MiB ZIP and exact five source/manifest entries. Encrypted backups include app source/state/files and private runtime records. Restore disables apps by default and makes pending/claimed timers need review. Source-only exports still omit private data. Legacy sos* commands delegate to apps/sos; migrated active runs need review. No automatic SMS on install/migration.
